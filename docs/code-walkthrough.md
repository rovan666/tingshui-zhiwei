# 代码导读：从一段波形到一条告警

> 给第一次接触项目的人看。建议先跑通，再按本文顺序读代码；不要只背算法名。
> 当前全部结果来自仿真，尚未接入真实水听器或公开水声数据集。

## 1. 先用一句话理解项目

这套程序把四个水听器收到的波形变成一条可展示的告警：**什么时候出现了异常、异常来自哪个方向、它更像哪一类声音。**

主入口是 [`run_pipeline.py`](../run_pipeline.py)。网页不重新计算算法，也不手填结果；它读取 [`src/viz/export_demo.py`](../src/viz/export_demo.py) 从同一套算法导出的 JSON。

## 2. 数据在各模块里长什么样

| 阶段 | 变量／文件 | 含义 |
|---|---|---|
| 原始波形 | `x_all: (4, N)` | 4 个通道、每通道 N 个采样点 |
| 单通道波形 | `mono: (N,)` | 取 CH1 做检测和分类，避免直接平均四通道造成相消 |
| 频域波形 | `X: (4, F)` | 对 1 秒分析窗的每个通道做 FFT |
| 告警 | `t_start/t_end/detection_stat_db` | 起止时间与检测统计量，不是输入 SNR |
| 测向 | `angles_deg/P_db/est_deg` | 扫描角、归一化方位谱、峰值角度 |
| 分类 | `label/prob` | 类别和未经校准的模型输出分数 |
| 网页数据 | `app/public/demo-data.json` | 波形包络、检测序列、方位谱、log-Mel、模型得分和场景真值 |

全局参数在 [`docs/algorithm-framework.md`](algorithm-framework.md)：采样率 96 kHz、四元圆阵、半径 0.0375 m、声速 1500 m/s。角度约定为 0° 指向 x 轴正方向，逆时针增加。

## 3. 主流程：`run_pipeline.py`

### 3.1 先定义场景，而不是假装采集到了真实数据

`FS`、`R`、`C` 分别是采样率、阵列半径和声速。`EVENTS` 明确写出三个仿真事件：

- 1—3 秒：船舶，60°，6 dB；
- 4—5 秒：人员拍水，120°，3 dB；
- 5.5—7 秒：鱼类活动，250°，0 dB。

主函数用固定种子 11 生成 8 秒、四通道高斯白噪声，再把三个事件加入指定时间窗。固定种子的意义是：同一版本代码在同一环境下可以复现，而不是每次演示碰运气。

### 3.2 `add_source()`：把同一个声音放到四个阵元上

声源到各阵元的距离不同，所以到达时间不同。程序先由方向计算单位向量 `u`，再算每个阵元的相对时延：

```text
τ_i = p_i · u / c
```

随后在频域乘相位因子完成分数时延，避免简单整数采样平移带来的误差。加入前还按“当前背景功率 × 目标 SNR”缩放信号，保证设定的 6、3、0 dB 确实对应加入信号与背景的功率比。

**读代码时抓住一点：** 四个通道不是四段互不相关的声音，而是同一个声源经过不同时延后，再叠加各自背景噪声。

### 3.3 检测与分类为什么只用 CH1

```python
mono = x_all[0]
alarms, dbg = cfar_detect(mono, FS, pfa=1e-2)
```

不同方向会让高频信号在四个通道间产生明显相位差。直接对四通道做普通平均可能相消，因此检测和分类使用参考通道 CH1；测向则必须保留四通道，因为方向信息就在通道间相位差里。

### 3.4 为什么每段告警要截成 1 秒

`analysis_window()` 以告警中心截取 96000 点，靠近记录边界时平移窗口。这样无论原始告警持续 0.02 秒还是 2 秒，分类器都收到固定长度输入。

这也带来一个限制：长事件只分析中心附近 1 秒，并没有把整段都送进当前 MLP。

### 3.5 测向与分类

对四通道分析窗做 FFT 后，`select_doa_band()` 按四通道平均功率寻找峰值频率，并取峰值附近最多 ±1.5 kHz 的频带。这里用平均功率而不是把复数频谱直接相加，避免反相通道互相抵消。

随后：

- `cbf_spectrum()` 用四通道频域数据计算方位谱；
- `classify()` 用 CH1 的 log-Mel 特征进行分类；
- 终端输出时间、方位、类别和模型得分。

`prob` 是 MLP 的最大 softmax 输出，**不是经过现实数据校准的置信度**。

## 4. 仿真层：声音和阵列从哪里来

### 4.1 `sim/uca_sim.py`

四个阵元位于圆周 45°、135°、225°、315°。`element_positions()` 返回 `(4, 2)` 坐标；`simulate_uca()` 生成一个带轻微调制的窄带信号，根据入射方向加入各通道时延，再按 SNR 加噪。

它返回时间轴、时域四通道、频域四通道和频率轴，主要用于 Day 1 和 MUSIC 对比实验。

### 4.2 `sim/sources.py`

这里不是采集数据，而是人为定义四类信号的统计结构：

| 类别 | 仿真结构 | 预期时频特征 |
|---|---|---|
| `ship` | 150/300/450 Hz 谐波、8 Hz 幅度调制和带限噪声 | 低频稳定线谱 |
| `human` | 3—5 个 1—8 kHz 衰减噪声脉冲 | 宽带、短时、间歇出现 |
| `fish` | 10—17 个 12—20 kHz 短促咔哒 | 高频、稀疏脉冲 |
| `noise` | 50 Hz—24 kHz 带限背景 | 无目标结构 |

这些规则让算法能跑通，也让分类任务比真实水声简单。训练和测试来自同一类生成器，因此不能把仿真测试准确率当作泛化到真实水域的证明。

## 5. 检测：`src/detect/cfar.py`

### 5.1 为什么不是固定阈值

固定阈值在背景变强时容易误报，在背景变弱时又可能漏报。CFAR 的核心是：**先用当前位置周围的参考单元估计背景，再根据背景动态决定门限。**

### 5.2 为什么有两个检测通道

1. **频率向谱线 CFAR：** 对每帧功率谱沿频率扫描。持续船舶线谱只要比左右邻近频带突出，就可能命中；不会因为持续时间长而被自己的时间参考窗吸收。
2. **时间向宽带能量 CFAR：** 比较当前帧总能量与前后参考窗。人员拍水不一定有稳定谱线，但会产生明显的宽带能量抬升。

两路命中取并集，再要求至少连续 4 帧才形成告警，最后合并间隔不超过 0.15 秒的相邻告警。这样既保留短促事件，也减少单帧毛刺直接成为告警。

### 5.3 0 dB 到底是什么

代码先把“功率／背景”与门限系数相除，得到归一化裕量，再取对数：

```text
归一化裕量 > 1  ⇔  10·log10(裕量) > 0 dB
```

所以页面和调试输出统一用 0 dB 判决线。`detection_stat_db` 只是检测统计量，不是声源 SNR，也不是分类把握。

### 5.4 为什么使用矩形窗

Hann 窗会让相邻 FFT 频点相关，破坏当前白噪声 CA-CFAR 中“参考单元近似独立”的假设，曾导致实测帧级虚警率偏高。当前频谱检测改用矩形窗分帧，并按实际参考单元数计算门限；频段边缘使用可用的单侧参考窗。

设计帧级 `pfa=0.01` 被平分给频谱和能量通道，各 0.005，再用并集上界分配预算。公式仍基于平方律单元近似指数分布，所以必须做实验校准。

当前固定仿真白噪声实验中，六档 SNR 的帧级虚警率为 0.00374—0.00517，低于本实验预算 0.01；这只适用于该仿真和样本规模。真实有色、非平稳噪声下必须重新校准。

## 6. 测向：`src/doa/`

### 6.1 CBF：哪个方向补偿后最整齐

[`cbf.py`](../src/doa/cbf.py) 对 721 个角度逐一计算理论时延，补偿各通道相位后叠加，再对频带内输出功率求平均。

如果扫描方向接近真实方向，各通道会更接近同相，叠加功率较大；方向不对则容易相互抵消。因此方位谱峰值就是估计方向。

优点是直观、稳健、适合先把链路跑通；缺点是主瓣较宽，分辨相邻声源的能力有限。

### 6.2 MUSIC：利用噪声子空间找尖峰

[`music.py`](../src/doa/music.py) 在指定窄带频点分帧取快拍，估计四通道协方差矩阵并做特征分解。已知信源数时，小特征值对应噪声子空间；真实方向的导向矢量应尽量与噪声子空间正交，所以其倒数谱出现尖峰。

需要特别注意：

- 必须合理指定 `n_sources`，且小于阵元数；
- 多途反射造成的相干信号可能使协方差矩阵退秩；
- 当前 MUSIC 是独立对比实验，主流水线仍使用 CBF；
- 尖锐谱峰不自动等于更高真实精度，需要独立实验验证。

## 7. 分类：`src/classify/`

### 7.1 `features.py`：把波形变成时频纹理

`logmel()` 对 1 秒波形分帧、加 Hann 窗、做 FFT 和功率谱，再用 40 个 Mel 三角滤波器合并频点，取对数并做整体均值方差归一化。

在当前默认参数下，1 秒输入得到约 `40 × 186` 的 log-Mel 特征。它类似一张“声音纹理图”：低频线谱、宽带拍水和高频咔哒呈现不同分布。

这里的 Mel 滤波器采用人耳感知刻度，是一种特征工程选择，不表示水下目标听觉与人耳相同。

### 7.2 `mlp.py`：训练与推理

`LABELS` 固定为 `ship/human/fish/noise`。`make_dataset()` 默认每类生成 200 条，共 800 条，随机打乱后按 80%／20% 划分训练与测试。

`train()` 使用一个 128 单元隐藏层的 sklearn MLP。推理时把 log-Mel 拉平成一维向量，`predict_proba()` 输出四类分数，取最大值对应类别。

当前记录中的 96.2% 是该仿真数据划分的测试准确率。由于训练与测试共享信号生成规则，这个数字不能外推为真实水声识别率；下一步应接入公开数据或实测数据，并按场景、航次或录制批次做独立划分，避免相近片段同时进入训练和测试。

## 8. 导出：`src/viz/export_demo.py`

这个脚本复用主流程的场景、加噪、检测、分析窗、选频和 CBF 函数，再导出：

- 四通道波形的 1600 桶最小／最大包络；
- CFAR 时间轴、归一化裕量、原始帧命中和 0 dB 门限；
- 每段告警的 CBF 方位谱、频带、估计角和场景真值；
- 每段告警的 log-Mel 与四类模型得分；
- 明确标注 `dataMode: simulation` 的元数据。

波形包络保留真实采样在每段时间桶内的最小值和最大值，是为了减少 JSON 体积，不是重新画一条随机波形。

`truth` 只用于页面展示估计误差，不作为分类或测向输入。当前导出脚本与 `run_pipeline.py` 有少量流程重复，后续可抽成共同流水线函数，降低两处逻辑漂移的风险。

## 9. 前端：`app/src/`

### 9.1 数据进入页面

`hooks/useDemoData.ts` 读取 `demo-data.json`，`types/demo.ts` 约束字段类型。读取失败时显示错误和重试按钮，不静默换成假数据。

### 9.2 `App.tsx` 管什么

主要状态包括当前时间、是否播放、倍速、选中告警和启用通道：

- 点击告警：暂停回放，跳到告警中心，右侧方位谱、log-Mel 和模型得分同步切换；
- 播放：用 `requestAnimationFrame` 推进时间游标，进入某段告警时联动选中；
- 时间拖动：暂停并跳到指定时刻；
- 通道按钮：只改变波形显示，不重新计算算法；
- 导出数据：下载当前页面实际使用的 JSON。

`BearingPlot.tsx`、`DetectionChart.tsx`、`LogMelPlot.tsx` 和 `WaveformChart.tsx` 分别负责对应图形。样式主要在 `App.css` 和 `index.css`。

“播放”只是固定仿真场景的交互回放，不是实时采集，也不是声音播放器。

## 10. 测试在防什么

`tests/test_detection_pipeline.py` 的 8 项测试覆盖：

1. 晚于源信号时长的事件仍写入正确时间窗；
2. 加入信号的实际 SNR 与设定一致；
3. 检测输出包含统计量和帧命中，不冒充 SNR；
4. 低频边缘谱线不会因参考窗越界而漏检；
5. 稀疏鱼类咔哒能形成事件告警；
6. 白噪声帧级虚警率低于当前设计预算；
7. DOA 选频使用通道平均功率，不被反相通道抵消；
8. 任意告警都能转成模型需要的 1 秒定长输入。

运行：

```bash
python -m unittest discover -s tests -v
```

前端 `app/ui.spec.ts` 另有桌面交互、375 px 移动布局、数据失败重试三项测试。测试通过说明这些指定行为未回归，不等于证明真实水域性能。

## 11. 想改项目时，从哪里下手

### 改场景

修改 `run_pipeline.py` 的 `EVENTS`，再依次运行主流水线和 `python -m src.viz.export_demo`。网页要看到变化，必须重新导出数据并刷新。

### 加一种仿真目标

在 `sim/sources.py` 添加生成器并注册到 `GENERATORS`，同步更新类别标签、训练集和前端中文标签。不要只加生成器就声称分类器已经支持新类别，模型需要重新训练和独立验证。

### 接入真实四通道数据

保持 `x_all: (4, N)`、采样率和通道顺序约定，替换场景生成部分即可复用后续接口。但必须重新检查同步、采样率、阵列坐标、通道极性、背景分布和 CFAR 门限，不能沿用当前性能结论。

### 换分类模型

保留“1 秒单通道波形进、类别和分数出”的接口可先独立替换。若改输入长度、特征维度或类别集合，必须同步修改训练、模型文件、导出器和前端类型，不能只说“接口兼容”。

## 12. 答辩最容易被问的几个问题

**为什么检测和分类不用四通道平均？** 因为不同方向的相位差可能让直接平均相消；当前用 CH1，方向信息交给四通道 CBF。

**为什么测向用 CBF，MUSIC 只作对比？** CBF 先把端到端链路稳定跑通；MUSIC 对信源数、相干和多途更敏感，当前还没有足够真实数据支撑把它直接替换进主链路。

**模型得分 95% 能否说准确率 95%？** 不能。单个样本的 softmax 分数、测试集准确率和现实置信度是三件不同的事。

**为什么结果看起来这么整齐？** 因为场景、随机种子和信号生成规则都已固定，目的是可复现演示，不是模拟所有真实复杂情况。

**现在能否采购和组装？** 还不能。当前公开仓库主要完成算法仿真和展示；`docs/hardware/BOM.md` 是草稿，结构、电气、水密和装配方案仍需进一步设计与验证。
