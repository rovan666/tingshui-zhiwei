## 2026-11-20（第二次修正）· SNR 与 CFAR 统计口径审查修正

**审查发现并已修复**
- `add_source()` 原 SNR 公式方向错误且未使用背景功率：旧场景中 ship/human/fish 标称 6/3/0 dB，实测约 0.02/3.02/6.02 dB。现在逐通道按 `背景功率 × snr_lin ÷ 时延后信号功率` 缩放；-6/0/6 dB 三组自动化实测均在 0.05 dB 误差内。
- 告警字段 `snr_est` 改为 `detection_stat_db`：它只是检测统计量，不是输入 SNR。频谱调试输出改为“功率比÷对应 CFAR 门限”的归一化裕量，统一 0 dB 判决线，并提供原始 `frame_hit`。
- 频谱与能量通道现在各分配 `pfa/2`，按并集上界控制总帧级预算；代码明确保留平方律指数分布近似，不再声称频点独立假设已经成立。
- `run_demo_cfar.py` 分开统计检测率、场景级虚警概率、帧级虚警率与虚警次数/小时；场景级指标不再直接和帧级设计 Pfa 画成同一口径。

**最新真实结果（全部为仿真数据）**
- 7 项 unittest 全部通过。
- `run_pipeline.py` 共 3 段告警：ship 1.01–3.00 s、60.9°、1.00；human 4.50–4.52 s、120.3°、1.00；fish 6.11–6.13 s、250.2°、0.95。类别均正确，最后一个数值是未校准的 MLP softmax 分数，不是现实置信度。
- CFAR 每个 SNR 40 次：-15 dB 检测率降为 0.53，-12～-3 dB 均 1.00；各档场景级虚警概率和成形虚警次数/小时本轮均为 0；**帧级虚警率实测 0.0217–0.0229，高于标称 0.01**，说明门限模型尚未校准，不能宣称实测 Pfa=0.01。
- 0 次场景虚警只代表本轮 40 个无目标场景未出现成形告警，不证明真实概率为 0。

**下一步**
1. 分析帧级虚警偏高的通道来源，必要时用更广分布模型或实测门限校准，不能为通过图而隐藏该结果。
2. 扩展多角度、多 SNR、多目标与真实公开数据验证；当前仍是单场景仿真 demo。
3. 上述口径固定后再做可视化，页面使用“检测统计量”“模型得分”等准确名称。

## 2026-11-20 · 全链路流水线修复并通过回归

**做了什么**
- 修复 `run_pipeline.py` 的事件写入错位：原实现先对零填充到 8 秒的源信号做 FFT，又从 `start` 处切片，导致 4 s 后的拍水和 5.5 s 后的鱼类信号几乎没有写入；现在只对源信号本身做分数时延，再完整写入目标时间窗。

- 新增 `tests/test_detection_pipeline.py` 5 项回归测试，均已先复现失败再修复，当前全部通过。

**真实运行结果（全部为仿真数据）**
